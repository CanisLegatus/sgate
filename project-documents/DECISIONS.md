# sgate

Публичный репозиторий: [CanisLegatus/sgate](https://github.com/CanisLegatus/sgate).

Помощник управляющего «Галамарта» для корректировки Web-заказа. Приложение ещё не реализовано. Целевой запуск: HTML/JavaScript в корпоративном браузере, без сервера. Python-скрипты ниже — инструменты исследования/разработки, не требования к пользователю приложения.

Контекст: [AGENTS.md](AGENTS.md), [актуальные правила](project-documents/05_BUSINESS_RULES.md), [результат проверки источников](project-documents/09_CONSISTENCY_AUDIT.md).

## Исследовательские инструменты

Python 3, только стандартная библиотека. Команды выполняются из корня проекта. XLSX не изменяются.

Просмотр уникальных параметров без создания нового файла для заполнения:

```bash
python3 -B scripts/extract_unique_values.py example-files/order-full.xlsx -
```

Выбранные поля: C/D/E/F/G/H/J и «Склад прихода товара»/«Комментарий»/«Предупреждения» (теперь AJ/AK/AL). В C/D/E параметры разбиваются по запятым, один параметр считается максимум один раз на товарную строку. Кубы так не делятся: запятая может быть десятичной. Строки групп/названий и пустые строки исключаются из товарной статистики.

Если вместо `-` передан путь, генератор создаёт **новый** Markdown и отказывается перезаписывать существующий. Единственный рабочий файл с пояснениями владельца — [order-full-unique-parameters.md](analysis/order-full-unique-parameters.md); его не перегенерировать поверх комментариев и не создавать параллельные пользовательские опросники.

Поиск точных значений запрета:

```bash
python3 -B scripts/inspect_cube_blocks.py example-files/order-full.xlsx
```

Полный аудит кубов и проверка качества данных, JSON в stdout:

```bash
python3 -B scripts/analyze_cubes.py example-files/order-full.xlsx
python3 -B scripts/audit_order_data.py example-files/order-full.xlsx
```

Сохранённые технические результаты: [кубы](analysis/cube-audit.json), [данные](analysis/data-audit.json). Они привязаны к SHA-256 исходника. После замены Excel проверять соответствие хеша и пересчитывать аудит, а не считать старые JSON автоматически актуальными.

Парсер поддерживает текущую и прежнюю схемы через заголовки. Внутренние логические ключи пока используют прежние буквы, mapping задаёт физическую колонку. КУБ нужен для аудита допуска: отсутствие колонки в старом cut вызывает ошибку, а не запрет по пустому кубу. Формулы, Excel-ошибки, отсутствующие/неоднозначные обязательные заголовки и неоднозначные товарные строки не интерпретируются молча. Исходные пустоты сохраняются для аудита; числовая бизнес-трактовка 0 описана отдельно в правилах.

## Проверки

```bash
python3 -B -m unittest discover -s tests -v
```

Проверяются независимое чтение обоих XLSX, сдвиг колонок, кубовые границы/запреты/ошибки, сохранённый полный аудит, арифметика исходных данных и четыре известных конфликта рекомендаций Web. Изменение исходника может закономерно потребовать пересмотра проверенных ожиданий. Это тесты исследовательских инструментов, не доказательство точности отсутствующего движка заказа. Сборки браузерного приложения пока нет.

## Публичный репозиторий и локальные данные

Excel-выгрузки `example-files/`, папка `analysis/` с производными данными/пояснениями и кэши не публикуются. Ссылки документации на эти локальные источники работают только в рабочем каталоге с соответствующими данными. Для интеграционных проверок нужны локальные full/cut и сохранённый cube-audit.json; без них проверки файлов пропускаются, автономные проверки правил работают.
