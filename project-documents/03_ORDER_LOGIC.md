# Процесс формирования и согласования заказа

Актуализировано 02.11.2026. Подробные бизнес-правила и их статусы ведутся **только в [05](05_BUSINESS_RULES.md)**. Этот файл описывает процесс и семантику полей, не дублирует журнал уточнений.

## Web-заказ и ручное переопределение

По объяснению владельца, Web формирует перечень и рекомендацию. В текущем полном файле Z — «Рек», AA — «Заказ УМ», AB — «Заказ итого».

| Рекомендация Z | Ручное AA | Итог по объяснению владельца |
| --- | --- | --- |
| Заполнено | Пусто | Используется Z |
| Заполнено | Заполнено | Используется AA |
| Пусто | Пусто | Нет добавленного количества |
| Пусто | Заполнено | Используется AA |

Пустое ручное поле — отсутствие переопределения, не команда записать 0. Для обнуления нужна явная корректировка; техническое поведение AA=0 и сохранение значения в интерфейсе ещё не проверены. В текущем Excel все 10 626 AA пусты, поэтому по файлу нельзя проверить ручное переопределение на реальном заполненном примере. Числовые пустые продажи и остатки, в отличие от команды AA, владелец подтвердил как нули.

Рекомендация Web — входное предложение, не источник бизнес-ограничений. В текущем файле обнаружены четыре рекомендации, конфликтующие с кратностью или доступностью. Владелец уточнил: если согласны с рекомендацией, не трогаем, если корректируем — соблюдаем наши ограничения; см. [проверку](09_CONSISTENCY_AUDIT.md).

## Работа помощника

1. Открыть локальное HTML/JS-приложение в корпоративном браузере, выбрать свежую выгрузку.
2. Определить день работы/четверги, проверить схему и данные. Исходные данные и рассчитанные значения хранить раздельно.
3. Учесть кубы, абсолютные запреты, продажи, остаток, уже едущие партии, кратность и доступность по [05](05_BUSINESS_RULES.md).
4. Показать предложения, объяснения и позиции для ручного контроля. Пользователь выбирает индивидуальную стратегию/процент от целевого запаса, меняет и согласует количества.
5. Перенести согласованные изменения в Web-заказ. Ручной перенос обсуждён и допустим; браузерная автоматизация обсуждалась, но способ её реализации не выбран.
6. Владелец лично проверяет и отправляет заказ логистам. Автоматическая отправка не входит в сценарий.

Это поведение первой рабочей версии реализовано в локальном HTML/JS; текущие формулы и ограничения описаны в [10](10_IMPLEMENTATION.md). Неустановленные формулы не заменять догадками. Разбор семи решений — в [06](06_ORDER_CASES.md), прогноз и условные примеры — в [08](08_FORECAST_PROPOSAL.md).
