# Первая рабочая версия — реализация 02.11.2026

## Запуск и архитектура

Открыть `sgate.html` двойным щелчком в Chrome/Edge. Это один HTML со встроенными CSS, JavaScript и SheetJS 0.20.3; сервер, интернет, Python и Node пользователю не нужны. `index.html` — тот же интерфейс из исходных локальных файлов. Сборка для разработчика: `npm run build`.

- `app/engine.js` — чистые бизнес-функции без DOM: кубы, прогноз, четверги, поставки, стратегии, замены, ограничения, проекции.
- `app/importer.js` — фактические ячейки XLSX независимо от ошибочного dimension/!ref, заголовки/две схемы, типы, группы, проверки дублей и ошибок.
- `app/session.js` — решения оставить/изменить, валидация, только подтверждённые изменения, сессии и защита от повреждённых данных.
- `app/main.js` — таблица с пагинацией/поиском/фильтрами, карточки, настройки, метрики, локальное сохранение и экспорт.
- `vendor/` — локальная библиотека и её лицензия, без CDN при запуске. CSP запрещает внешние сетевые соединения; браузерные тесты проверяют отсутствие HTTP-запросов.

## Реализованные утверждённые правила

38 полей и старая схема; кубы и абсолютные запреты; взвешенный прогноз 10/20/30/40; нули пустых продаж/остатков; защита 25%; календарь до второго четверга; K/L для наших корректировок; сохранение принятого исходного Web, в том числе конфликтного K/L; AE один раз с дополнением недостачи; базовые направленные замены; пользовательские стратегии/процент от цели; ручной контроль КОШ/уценки; МТЗ справочно; 352 м² и розничные метрики. Фактическая отправка в Web не реализована и не автоматизируется.

Все предложения требуют подтверждения. «Оставить исходный» сохраняет исходную рекомендацию/имеющийся ввод УМ и не создаёт новой команды. Положительный заказ запрещённого/неопределённого по кубу товара не допускается. Явный 0 выгружается как 0, а не пустота. Для замен проверяется, не останутся ли оба товара в заказе, в том числе из-за непросмотренного исходного количества.

## Стартовые формулы — технические решения, не новые слова владельца

Эти части не были окончательно формализованы владельцем. Они явно показаны в интерфейсе и настраиваются:

- Расход до даты распределён равномерно как D/7; данные о днях недели отсутствуют. Четверги считаются от даты расчёта. В четверг по умолчанию выбирается следующий четверг, с предупреждением.
- Одна неделя покрытия после поступления — стартовая настройка, изменяется глобально. Защищённому товару добавляется 0,25D.
- В режиме «по потребности» базовая цель после поступления — это покрытие с резервом. Для ручных стратегий авто-база — максимум текущего остатка и минимальной цели. Пользователь может задать явную базу; +10% к 100 даёт 110 без повторного самоперемножения.
- Цель после процента не ниже покрытия; до неё вычитается прогнозный физический остаток к поступлению, уже учитывающий AE. Положительная недостача округляется вверх до K и ограничивается floor(L/K)×K. Политика округления уменьшения — стартовая консервативная реализация, не утверждённое универсальное правило владельца.
- Потерянный спрос до прихода не превращается в задолженность, которую нужно повторно заказать. Он виден как предупреждение; запас обнуляется физически, а знак минус в проекции показывает дефицит.
- Для AE по умолчанию ближайший четверг, с явной подписью допущения; глобальная или индивидуальная дата может быть изменена. AF не добавляется в AE.
- По мерчдатам год оценивается относительно расчётного года; равенство даты и неоднозначный переход года требуют контроля, а не скрытого решения. Эти признаки не создают автоматической надбавки.

При выборе «держим»/«увеличиваем» и настройке базы пользователь управляет более высоким запасом, чем минимальная недельная норма. Семь прошлых решений не зашиты по артикулам и не объявлены точно воспроизводимыми автоматически новой взвешенной формулой. Проверено, что все семь решений допустимы, сохраняются и экспортируются; сценарии A/B/C проверены отдельно.

## Пики, промо и отрицательные продажи

Пики не очищаются. Простой диагностический признак скачка лишь показывает предупреждение; ни исходный ряд, ни D из-за него не изменяются. Можно вручную задать прогноз.

Границы недель неизвестны, поэтому промонедели не угадываются. Есть ручная разметка недель и ручной прогноз. Пока промо не разобрано, автопредложение помечено как требующее проверки и не применяется кнопкой принятия предложения; доступны осознанное сохранение исходного или собственная корректировка. Это не автоматическая точная двухфазная модель промо.

В текущем Excel обнаружены отрицательные недели у 249-110, 314-140, 822-288. Их смысл владельцем не объяснён. Они сохраняются как исходные значения, не заменяются нулями; без ручного прогноза товар требует разбора. Отрицательные Web-дни запаса также показаны как есть и не используются как вычислительная норма. После сохранения исходных отрицательных продаж сумма недель совпадает с U во всех строках.

## Сохранение и перенос

Автосохранение хранит настройки/решения локально по отпечатку файла. Для продолжения открыть тот же Excel. Если браузер не разрешает localStorage/квота исчерпана, приложение сообщает об этом; резервная JSON-сессия работает отдельно и содержит исходные строки, настройки и решения. Изменение даты/параметров снимает неактуальные подтверждения. Повреждённая сессия не должна менять текущую.

CSV содержит только согласованные изменённые количества для ручного переноса. Excel-отчёт имеет листы изменений, всех проверенных показателей и параметров. Оставленные исходные количества в список команд не попадают. Непросмотренные товары сохраняют исходный заказ и явно обозначены в сводке; экспорт не означает, что весь заказ проверен. JSON-резерв и исходный Excel не публикуются в GitHub.

## Проверка

`npm test` — чистая логика и интеграция с локальными образцами. `npm run test:browser` — настоящий Chromium, открывающий file:// без сервера; демо, стратегии/валидация, CSV/Excel с нулём, JSON roundtrip, повреждённая сессия, мобильный экран, full/cut и отсутствие HTTP-запросов. Старые Python-проверки остаются.

Полная выгрузка: 10 626 товаров; кубы 6 801/76/235/3 514; положительный остаток 7 665 SKU; розничная стоимость 18 156 991,30 руб. Без локальных Excel интеграционные проверки пропускаются; автономные тесты и браузерное демо работают. Скриншоты/трассы с локальными данными исключены из Git.

Финальный прогон этой версии: **24 Node + 6 browser + 10 Python — успешно**. Все пять исполняемых скриптов standalone дополнительно проверяются сборкой через vm.Script. Проверены неизменность исходных Excel, локальные ссылки и отсутствие внешних src/href в автономной сборке.
