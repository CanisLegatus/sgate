# Текущее состояние проекта

Обновлено 02.11.2026. Последнее поручение владельца выполнено в версии правил **sgate-2.1**: загрузка сразу формирует наш заказ, согласования полностью удалены. Предыдущий режим сохранения достаточного Web признан ошибкой агента и заменён; не возвращать его при следующей разработке. Добавлен общий safety stock по прямому поручению владельца после примера 022-344. Актуальная спецификация — [05, R23/R24](05_BUSINESS_RULES.md), технические формулы/ограничения — [10](10_IMPLEMENTATION.md).

## Запуск и поведение

Открыть `sgate.html` двойным щелчком в Chrome/Edge; сервер, интернет и установка не нужны. Исходники: `index.html`, `app/engine.js`, `importer.js`, `session.js`, `main.js`, `styles.css`; сборка `npm run build`.

Количество рассчитывается по нашей потребности, а не сохраняется по достаточности Web. Списки: все изменения, проблемные, уменьшено, увеличено, обнулено, без изменений, ручные количества, контроль, все товары. Все определённые количества сразу входят в метрики и CSV/XLSX; кнопок принятия, записей согласований и подписей решений нет.

Общая стратегия/процент над таблицей сразу пересчитывают все товары и сбрасывают ручные количества (подписано в UI). Индивидуальные прогнозы/базы/даты партий и выбор замен сохраняются. Ручная правка количества действует сразу; можно вернуть авторасчёт. Правка параметров товара возвращает его к автоматическому количеству. Смена только календаря сохраняет ручные количества. Допуски, K/L и запрет двух положительных заказов в группе действуют также для ручного ввода.

Неизвестное количество — null, не 0 и не Web. Причина явно показана в проблемах; такие строки исключены из CSV изменений, представлены с причиной и пустым количеством в XLSX. Частичность стоимости/проекции обозначена: заказ учитывает известные количества, проекция — строки с известными количеством и прогнозом. Остальные товары рассчитываются независимо. Сложные промо/отрицательные продажи/неоднозначные замены не считаются автоматически разрешёнными.

## Страховой запас

Для всех товаров при D>0 reserve=max(1 шт., D×p/100); глобальный p по умолчанию 25%, для защищённых эффективный p не ниже 25%. При D=0 reserve=0. Включён в цель до округления итогового заказа по K, не прибавляется к Web или AE. Настройка процента — в «Настройках расчёта», резерв виден в карточке и Excel. Смена процента резерва сохраняет ручные количества; недостача резерва по ним помечается проблемой. Резерв не отменяет запреты/кратность/склад.

## Сохранение, проверки и продолжение

JSON-сессия v2 и автосохранение содержат настройки, параметры, ручные количества и выбор замен. При восстановлении результаты вычисляются заново. Старые сессии 1.0/1.1 мигрируются без согласований/старых индивидуальных стратегий; сессии 2.0 сохраняют ручной ввод, получают резерв 25% по умолчанию и пересчитываются. CSV — все определённые изменения; XLSX — изменения, полный наш заказ, проблемные и параметры. Отправка в Web остаётся за владельцем, не автоматизирована.

Финальный прогон версии 2.1: **34 Node-теста и 8 браузерных тестов — успешно**, сборка проверила синтаксис всех пяти встроенных скриптов.

Проверки: `npm test` (логика/реальный отчёт/инварианты/ручные изменения/миграция); `npm run test:browser` (file://, импорт→расчёт→выгрузка без согласований, глобальная стратегия, редактор, JSON, full/cut, мобильный экран, отсутствие HTTP). Python-проверки чтения/аудита остаются. Браузерные артефакты исключены из Git. Проверки не доказывают совпадение формулы с любым будущим решением владельца; базовые цели и остальная неопределённость описаны в 04/10.
