## Проект

Помощник управляющего «Галамарта» для еженедельной корректировки Web-заказа, сейчас занимающей около 3–5 часов. Заказ в день работы со свежим файлом, обычно пятница–понедельник, поставки по четвергам. Первая версия — HTML/JavaScript без сервера, открытие в корпоративном браузере; Python только для исследования/разработки. Первая рабочая версия реализована: пользовательский файл sgate.html, исходники в app/.

Приложение сразу рассчитывает и применяет наш заказ. Владелец выбирает общую стратегию/процент, может переопределить количество и делает финальную отправку логистам лично. Автоматическая отправка не входит в сценарий. Ручной перенос предусмотрен обсуждением; браузерная автоматизация ещё не выбрана как реализация.

## Критичные правила

- Поля искать по заголовкам. Сейчас I=куб товара, Y=куб магазина, Z=Рек, AA=УМ, AB=итог, AE=товар в поставке, AF=распределения, AK=комментарий, AL=предупреждения.
- ЗО/ЗО вр/ЗО сеть/!ВНЕ_АМ-1 запрещают новый заказ. Пустой куб магазина или уровень товара выше его уровня — также запрет, в том числе для защищённых товаров. Уровни сравнивать как числа внутри одинаковой категории, запятая/точка — десятичные разделители. Не удалять ! из имени.
- Наше скорректированное положительное количество кратно K и не выше L; исходный Web использовать для сравнения, а не обхода формулы/ограничений. Кубовые запреты не отменены. F=не для продажи игнорируется: старый запрет отменён владельцем. МТЗ обычно игнорируется, исключения ещё не описаны.
- Пустые числовые продажи/остатки — 0. Пустое AA — отсутствие ручной команды; не обнулять из-за него рекомендацию. Технический ввод явного нуля в Web ещё не проверен.
- Q/R/S/T имеют веса 10/20/30/40%. Владелец попросил осторожнее с очисткой; автоматическое срезание пиков и его пороги пока не утверждены, исходные продажи сохранять. Не исключать нулевые недели из прогноза из-за исходных пустот.
- При D>0 страховой запас для всех товаров=max(1 шт., D×процент/100), общий процент по умолчанию 25%; для защищённых эффективный процент не ниже 25%. При D=0 резерв 0. Резерв включать в цель до округления всего заказа по K. Проверять пропуск заказа до второго четверга; не подменять это всегда 14 днями или двумя неделями после поступления.
- AE уменьшает потребность; недостачу дополнять, одну партию не учитывать дважды. AF не приравнивать автоматически к AE.
- Общую стратегию и процент выбирает пользователь; смена немедленно пересчитывает все товары и сбрасывает ручные количества. Процент от целевого запаса товара. Формула получения базовой цели и часть пограничных случаев ещё не согласованы.
- Сезонный контроль отключён; КОШ/уценка — ручной контроль. Даты мерчкатегорий сравниваются с поставкой.
- Старый товар в однозначной замене приоритетен; при его запрете и V=0 выбирать новый с проверкой допуска. Цикл/противоречие — одна группа для разбора, не угадывать старый артикул и не суммировать спрос. Два участника с положительным заказом запрещены.
- Основной режим сразу формирует наш заказ по формулам до второго четверга: уменьшает, увеличивает, обнуляет, оставляет совпадения. Нет согласований, принятий, подписей решений или экспорта только подтверждённых строк. Неопределённое количество — null, не 0 и не Web; список проблем и экспорт явно это показывают.
- Наполнение: торговая площадь 352 м², розничные цены N, целевых нормативов нет.

Текущие технические решения реализации (локальный SheetJS, сессии и UX) описаны в 10; не выдавать их за отдельное утверждение владельца.
